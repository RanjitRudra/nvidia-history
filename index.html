Chapter 01
GPU vs CPU
The foundational concept — why GPUs exist and when they win over CPUs.
The Master Analogy
CPU = Few World-Class Surgeons | GPU = Army of Assistants
For complex sequential decisions requiring expertise, surgeons win. For mass parallel repetitive work, the army wins. AI training is firmly army territory — billions of independent matrix multiplications running simultaneously.

The Critical Insight
Dependent vs Independent Instructions
DEPENDENT — CPU WINS (must execute sequentially) R1 = R2 + R3 step 1 R4 = R1 x R5 MUST WAIT — uses R1 from step 1 R6 = R4 / R7 MUST WAIT — uses R4 from step 2 1000 dependent instructions = 1000 cycles even on a GPU INDEPENDENT — GPU WINS (run all at once) R1 = R2 + R3 all three run simultaneously R4 = R5 x R6 on different cores R7 = R8 / R9 in one cycle 1000 independent instructions = 1 cycle on 1000 GPU cores
GPU Hardware Hierarchy
4 Levels: GPU → SM → Partition → Execution Units
GPU (entire card) └── SMs (Streaming Multiprocessors) ← most important unit └── Partitions (4 per SM in Volta+) └── Execution Units ├── CUDA Cores (FP32, FP64, INT) ├── Tensor Cores (matrix math / AI) ├── Special Function Units (log, sin, cos) ├── Load/Store Units ├── Warp Scheduler + Dispatcher └── Register File L1 Cache = inside each SM | L2 Cache = shared across entire GPU
"GPUs are NOT better than CPUs in all circumstances. CPUs win on sequential dependent workloads. GPUs win on massively parallel independent workloads. The myth that GPUs are universally better is exactly that — a myth."— GPU Computing Fundamentals

Third-Party Manufacturers
Consumer vs Data Center GPU Distribution
NVIDIA licenses chip designs to ASUS, MSI, Gigabyte for consumer GPUs — causing minor differences in clock speeds and cooling designs. Data center GPUs (A100, H100, H200, B200) are NVIDIA-controlled directly or through DGX partnerships. No third-party versions of data center GPUs exist.

Chapter 08
Performance Parameters
The 4 factors that determine GPU performance. Core count alone means nothing.
Parameter 1
Memory Bandwidth (GB/s or TB/s)
Bus Width x Memory Speed x Technology = Bandwidth. Bus Width = road lanes. Memory Speed = car speed. Together they determine how much data flows to the cores per second. HBM3e gives the H200 a 4.8 TB/s highway — 13x wider bus than the RTX 3090 despite sharing the Ampere architecture concept.
Parameter 2
Instructions Throughput (TFLOPS)
Core Count x Core Speed = TFLOPS. Use TFLOPS as a single number — it captures both factors and lets you skip raw core count debates. When reading a whitepaper, go straight to the TFLOPS table by precision (FP64, FP32, FP16, BF16, FP8).
Parameter 3
Energy Consumption (TDP in Watts)
HPC GPUs deliberately run at lower clock speeds than consumer GPUs to reduce power consumption. Multiplied across 1,000+ nodes in a data center, every watt saved = significant operational cost reduction. Your 95-node DGX cluster is a perfect example of why this matters at scale.
Parameter 4
New Hardware Units / Features
The biggest performance leaps come from entirely new units, not just more cores. Tensor Cores (Volta 2017) delivered 8x AI performance improvement over Pascal without changing core counts. The Transformer Engine (Hopper 2022) further revolutionised LLM training and inference.

SIMT — The Core of GPU Parallelism
Single Instruction Multiple Threads
Vector Addition — the classic SIMT example: Vector A: [1, 2, 3, 4, 5...] Vector B: [9, 8, 7, 6, 5...] GPU (SIMT approach): Thread 1 adds A[1]+B[1] all Thread 2 adds A[2]+B[2] run Thread 3 adds A[3]+B[3] simultaneously Same INSTRUCTION (add) on different DATA = SIMT Warp = exactly 32 threads, same instruction, different data elements Warp Divergence (if/else inside a warp) = forces serialisation = kills perf
The Tensor Core Paradox
Ampere Has Fewer Tensor Cores But More Throughput
Volta: 640 Tensor Cores (2nd gen) = 125 TFLOPS FP16 Ampere: 432 Tensor Cores (3rd gen) = 312 TFLOPS FP16 Each Ampere Tensor Core is 2.5x more capable than each Volta Tensor Core RULE: NEVER judge by count alone. TFLOPS is the only honest comparison.

What is a Warp and why does it matter for CUDA programming?
Click to reveal answer
A Warp = exactly 32 threads that execute the same instruction simultaneously on different data (SIMT). All 32 threads are scheduled by the Warp Scheduler and dispatched in one clock cycle. Warp Divergence — when threads within a warp take different code paths (if/else branching) — forces serialisation and kills parallelism. Avoiding warp divergence is one of the most critical CUDA optimisation rules.
When were Tensor Cores introduced and what do they do?
Click to reveal answer
Volta architecture, 2017. Tensor Cores are specialised units for matrix multiplication — the fundamental operation of all neural networks. They delivered an 8x-12x performance increase for AI vs Pascal. Each generation improved: Volta (FP16), Turing (INT8/4), Ampere (BF16, TF32, sparsity), Hopper (FP8, Transformer Engine), Blackwell (FP4), Rubin (6th gen). Always compare Tensor Core generations by TFLOPS not count.
What is the difference between H100 and H200? What chip do they share?
Click to reveal answer
Both use the same GH100 chip (Hopper architecture, CC 9.0). The H200 upgrade is entirely in the memory subsystem: 141GB HBM3e at 4.8 TB/s versus H100s 80GB HBM3 at 3.35 TB/s. 1.76x more memory, 1.43x more bandwidth. Same compute performance, significantly better for large model inference where memory is the bottleneck. Both require minimum CUDA 11.8.
Why does Ampere have fewer Tensor Cores (432) than Volta (640)?
Click to reveal answer
Because each 3rd gen Ampere Tensor Core is approximately 2.5x more capable than each 2nd gen Volta Tensor Core. Ampere Tensor Cores support more data types (BF16, TF32) and deliver higher throughput per core. Result: 432 Ampere Tensor Cores = 312 TFLOPS versus 640 Volta Tensor Cores = 125 TFLOPS. Always compare TFLOPS not raw counts.
What is the naming convention for NVIDIA GPU chips?
Click to reveal answer
G + Architecture initial letter + number. Examples: GF100 (Fermi), GK110 (Kepler), GM200 (Maxwell), GP100 (Pascal), GV100 (Volta), GA100 (Ampere), GH100 (Hopper), GB200 (Blackwell), R200 (Rubin). From Pascal onwards, HPC GPUs use the pattern architecture-letter-100: P100, V100, A100, H100. Lower chip number within a family = higher tier (GA100 > GA106).
What are the 4 key parameters for evaluating GPU performance?
Click to reveal answer
1. Memory Bandwidth (GB/s or TB/s — bus width x memory speed x technology type). 2. Instructions Throughput (TFLOPS — core count x clock speed, captures both in one number). 3. Energy Consumption (TDP in watts — critical at data center scale). 4. New Hardware Units (Tensor Cores, Transformer Engine — biggest leaps come from new units not more cores). Never judge by core count alone.

What are the headline specs of the Vera Rubin R200?

Why do data center GPUs have no cooling fan?
Click to reveal answer
Data center GPUs in the Tesla generation (A100, H100, H200, B200) are installed in server chassis that provide managed external airflow or liquid cooling systems. An onboard fan would be redundant, adds cost, and creates reliability concerns at scale. Consumer GPUs need onboard fans because desktops and workstations do not provide managed airflow. The presence or absence of a fan is the fastest visual way to identify HPC versus consumer GPUs.
Why is CUDA NVIDIA's biggest competitive moat?
Click to reveal answer
CUDA launched in 2006 — opening NVIDIA GPUs to general-purpose parallel computing. Every major AI framework (PyTorch, TensorFlow, JAX), every HPC toolkit, and every AI researcher has been building on CUDA for 18+ years. Switching away requires rewriting enormous software ecosystems. This creates deep ecosystem lock-in that is harder to overcome than any hardware advantage. NVIDIA's deepest competitive moat is not the hardware — it is the CUDA software ecosystem built on top of it.
What is the key innovation of Blackwell vs Hopper in hardware design?
Click to reveal answer
Dual-die chiplet design — two reticle-sized GPU dies connected by a 10 TB/s NV-HBI (NVLink High-Bandwidth Interface) chip-to-chip interconnect. This bypasses the approximately 800mm2 reticle size limit of TSMC's process, enabling 208 billion transistors on one package versus Hopper's 80 billion. The two dies appear as a single logical GPU to software. Plus: 5th gen Tensor Cores with native FP4, 2nd gen Transformer Engine, NVLink 5 at 1.8 TB/s, and approximately 4x H100 inference throughput.
